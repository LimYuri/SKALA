## 3. 실행 및 캡처 체크리스트

API 키를 환경변수로 설정하고 `./gradlew bootRun`을 실행한 뒤 Swagger에서 아래 화면을 캡처한다.

- [ ] 서버 시작 성공 로그와 Swagger의 `/lab2` API 3개 목록
- [ ] 첫 번째 POST `/lab2/ingest`의 문서별 source/chunks 응답
- [ ] 두 번째 POST `/lab2/ingest` 응답: 청크 수가 첫 번째와 동일함을 나란히 제시
- [ ] GET `/lab2/retrieve?q=반품 기한&topK=4`: score/source/snippet과 `return-policy`
- [ ] 표현 변형 검색: `물건 돌려보내려면 며칠 안에 해야 해요?`가 `return-policy`를 찾음
- [ ] 없는 질문 검색: `우주 배송`의 결과가 없거나 점수가 낮음을 보여 주는 화면
- [ ] POST `/lab2/ask` 정상 답변: answer, sources, grounded=true
- [ ] POST `/lab2/ask` 없는 질문: `확인되지 않습니다.`, 빈 sources, grounded=false
- [ ] `./gradlew test`의 BUILD SUCCESSFUL
- [ ] API 키가 있을 때 `./gradlew test -Peval`의 `EVAL_RESULT pass=x/10`과 BUILD SUCCESSFUL
- [ ] 기준 A와 변경 실험 1개 이상의 환경변수/실행 결과 비교

각 캡처 아래에는 `입력`, `출력`, `확인한 요구사항`, `해석`을 1~3문장으로 작성한다. API 키는 화면에 절대 노출하지 않는다.

## 6. 예상 감점 포인트와 개선 피드백

1. 실제 기존 프로젝트가 Spring AI 1.0.x이거나 패키지가 다르면 그대로 복사할 때 컴파일 오류가 날 수 있다. `README.md`의 이식 지점을 먼저 맞춘다.
2. 짧은 문서는 400토큰에서 문서당 1청크만 나올 수 있다. 교안의 `chunks: 7`은 예시이므로 개수 자체보다 재인제스트 전후 동일성을 증명한다.
3. `우주 배송`은 `배송` 단어 때문에 0.5 이상으로 검색될 가능성이 있다. 실제 점수 분포를 보고 threshold를 조정하고, 답변 프롬프트가 최종적으로 unknown을 반환하는지도 함께 캡처한다.
4. SimpleVectorStore는 메모리 기반이라 서버 재시작 시 재인제스트가 필요하다. 기존 프로젝트가 영속 VectorStore를 제공하면 그것을 유지하는 편이 낫다.
5. 문자 기반 overlap은 교안의 `20%`를 실험하기 쉽게 만든 보조 구현이다. 정확한 토큰 20%가 평가 조건이면 토큰 단위 overlap을 지원하는 splitter로 교체한다.
6. 제출 PDF에는 키, 전체 환경변수, 개인 경로가 보이지 않게 자른다. 결과 숫자와 질문/응답은 보이게 유지한다.
